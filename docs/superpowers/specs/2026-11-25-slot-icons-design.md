# One icon per equipment slot on Durability keys — design

Date: 2026-11-25
Branch: `feature/slot-icons` (from `develop`)
Status: approved by the user on 2026-11-25.
Builds on: `2026-11-23-slot-durability-design.md` (per-item Durability key, `SlotTable`)

## Intent

Every Durability key shows the same armor drawing today; only its colors change with the state. The user
wants each key to show **a drawing of its item** (a helmet for Head, greaves for Legs, boots for Feet, a
sword for Main hand…) so a key is recognized at a glance, **keeping the color change** (ok / warn /
critical / no data).

## Goals

- One silhouette per slot (the 11 slots of `SLOT_KEYS`), each in the 4 existing state palettes.
- A specific-item key shows its slot's silhouette.
- The **"Most damaged"** key shows the silhouette of the item that is the most damaged right now (user's
  choice "B"), found in the `SlotTable`. When the table has no numeric value yet, it shows the generic
  armor (today's icon).
- User documentation updated once validated in game, with the icons shown.

## Non-goals

- Game icons or the real item's icon: Blizzard art cannot be shipped, and the pixel channel only carries a
  few bytes.
- New states, new colors, or a different color threshold.
- Changing the action-list icon (`icon.svg`) or the manifest's default state image (generic armor stays).
- Changing the key titles.

## Anti-goals

- Slowing down the "Most damaged" key: its percent and color stay live from field 0; only the drawing comes
  from the table.
- 44 hand-maintained files that drift apart.

## Approaches

1. **SVG files generated by a script (chosen by the user).** `tools/make-slot-icons.mjs` holds one
   silhouette per slot and the 4 palettes and writes `imgs/actions/durability/<slot>/<state>.svg`
   (44 committed files). The plugin picks a file path from slot + state. Same pattern as `npm run icon`;
   the files can be viewed and shown in the docs.
2. SVG built at runtime as a `data:image/svg+xml` URI. One source, no files, but the icons are invisible
   outside Stream Deck and it departs from today's file-path images.
3. 44 hand-drawn files. Rejected: a palette change means editing 44 files.

## Design

- **Palettes** (unchanged, taken from today's files): ok = background `#000000`, drawing `#E8E8E8`;
  warn = `#F2C200` / `#1A1A1A`; critical = `#C8102E` / `#E8E8E8`; nodata = `#4A4A4A` / `#8A8A8A`.
  Detail lines are drawn in the background color, as today.
- **Generator** `tools/make-slot-icons.mjs` (`npm run slot-icons`, root): exports the SVG text per
  slot/state and writes the files. The generic armor files (`durability/<state>.svg`) are generated by the
  same script from the current armor path, so every palette lives in one place. A test checks that every
  file on disk equals the generator output (guards drift and missing files).
- **View** (`src/durability/view.ts`): `imageFor(state, slot?)` → `imgs/actions/durability/<slot>/<state>.svg`
  with a slot, `imgs/actions/durability/<state>.svg` without.
  - Specific-item key: its slot's silhouette; "empty", "n/a" and no data use the slot's nodata (gray)
    image, as today but with the slot drawing.
  - "Most damaged" key: percent and state from field 0 (unchanged). Drawing = first slot in `SLOT_KEYS` order
    whose `SlotTable` value equals field 0's percent exactly (`SlotTable.slotWith`), so the drawing never
    contradicts the shown percent. Field 0 at 100 % (nothing damaged), no slot holding that percent yet, or
    field 0 no data → generic armor. (Changed after the branch review: "lowest table value" showed a helmet
    at 100 % and could name a stale slot for a few seconds.)
- **Silhouettes**: simple flat shapes in the style of the current armor, 144×144, readable at key size:
  Head helmet, Shoulders pauldrons, Chest the current armor, Waist belt with buckle, Legs greaves,
  Feet boots, Wrists bracer, Hands gauntlet, Main hand sword, Off hand shield, Ranged bow.
